# visarun — справочник виз для граждан РФ

Веб-сервис «куда поехать»: живой справочник из 250+ стран с визовым статусом (безвиз / eVisa / eTA / нужна виза), сроками пребывания, интерактивной картой мира и подробными карточками стран со ссылками на первоисточники.

---

## Задача

Агрегаторы визовой информации для россиян — это либо устаревшие таблицы, либо SEO-мусор с датами 2019 года. Я собрал сервис, который:

- отвечает на главный вопрос быстро: ищешь страну → видишь статус, срок пребывания, ссылку на первоисточник (pravo.gov.ru, МИД РФ);
- фильтруется по тому, как люди выбирают: «куда безвиз / с eVisa / где хватит внутреннего паспорта», по регионам, Шенгену, СНГ;
- не проигрывает при росте: вся база в PostgreSQL, страница отдаёт данные из SQL, а не из хардкода.

Для меня это practice-кейс **end-to-end инженера**: от схемы данных в PostgreSQL до CI/CD с деплоем на Linux-сервер через systemd.

## Что умеет

| Возможность | Как устроено |
|---|---|
| Таблица стран с фильтрами | статус визы / регионы (ЮВА, ЛатАм, Европа, Восточная Европа) / Шенген / СНГ / «въезд по внутреннему паспорту» |
| Умный поиск | нормализация ё→е, поиск по префиксу, словарь алиасов («США», «Штаты», «Америка» → «Соединённые Штаты»; экранирование LIKE-символов) |
| Сортировка по колонкам | страна / статус / дни (безопасный whitelist колонок, NULLS LAST) |
| Карточка страны | визовые правила, даты подписания/вступления, источники, столица и города, этнический и религиозный состав, объекты ЮНЕСКО, курсы валют ЦБ |
| Карта мира | интерактивная SVG-карта всего мира одним файлом, цвет = статус визы, клик → карточка |
| HTMX-обновления | таблица перезагружается без полной перерисовки (частичные шаблоны) |
| Живая статистика | счётчики под фильтрами считаются из базы («безвиз — N стран») |

Конкретный пример карточки: Таиланд — соглашение 2005 года, 30 дней с 2026-го, курс бата, состав населения и объекты ЮНЕСКО — всё с указанием источника.

## Стек и архитектура

```
PostgreSQL ──► Django 4.2 (views на чистом SQL) ──► HTMX + шаблоны Django
    ▲                                                       │
    └── db/tables.sql (схема), db/import.sql (данные)       ▼
                                                      SVG/JS-статика
```

- **Backend:** Django 4.2, Python 3.11. Views читают данные **чистым SQL через psycopg2** — Django-ORM сознательно не используется: легаси-схема загружается psql-скриптами (`db/tables.sql` — DDL, `db/import.sql` — данные).
- **БД:** PostgreSQL; справочники стран по ISO-3166 (alpha-2/alpha-3, регионы, подрегионы), группы стран (Шенген, СНГ), отдельная таблица визовых правил.
- **Frontend:** HTMX, vanilla JS (`table.js`, `map.js`, `currency.js`), ~250 SVG-флагов и единая карта мира `world.svg`.
- **Безопасность:** параметризованные запросы везде; колонки сортировки — по whitelist; `%`/`_` в поиске экранируются; URL-алиасы (turkey → turkiye) обрабатываются на уровне views.
- **Продакшн:** gunicorn + systemd (`visarun.service`).

## CI/CD (GitHub Actions)

`push → main` автоматически:
1. деплой по SSH (appleboy/ssh-action, секреты — в GitHub Secrets);
2. `git pull` → `pip install -r requirements.txt` → `migrate` → `collectstatic`;
3. обновление данных: `psql -f db/import.sql`;
4. `systemctl restart visarun.service`.

## Как запустить локально

Требования: Python 3.10+, PostgreSQL 14+.

```bash
# 1. Код и зависимости
git clone https://github.com/xip2/visarun.git
cd visarun
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# 2. База данных: схема
createdb visarun
psql -d visarun -f db/tables.sql

# 3. Настройки подключения к БД — в visarun/settings.py

# 4. Данные
psql -d visarun -f db/import.sql

# 5. Запуск
python manage.py migrate --noinput
python manage.py collectstatic --noinput
python manage.py runserver
```

Открыть `http://127.0.0.1:8000/` — карта мира; `/countries/` — таблица с фильтрами и поиском; `/help/` — расшифровка визовых статусов со счётчиками из базы.

## Что было сложным

- **Легаси-схема.** Данные приходили из CSV-выгрузок; ORM-модели пришлось снять и работать с таблицами «как они есть», через сырой SQL. Меньше абстракций — больше контроля при import-перезгрузке.
- **Поисковый UX на русском.** «США», «Америка», «Коты», «Кот д'Ивуар», ё/е, лишние символы в названиях из выгрузки — построил словарь алиасов + нормализацию, поиск по префиксу с двумя стратегиями (название ИЛИ алиас).
- **Надёжный деплой одной командой.** GitHub Actions: SSH → обновление кода → миграции → перезаливка данных через psql → рестарт сервиса. Никакого ручного сопровождения на сервере.

## Источники данных

Визовые правила и факты приводятся со ссылками на первоисточники: `publication.pravo.gov.ru`, МИД РФ, информационные агентства, Википедия. У каждой ручной карточки есть поля `source_label` и `source_url` — источник видно прямо на странице.
